## Ajax 总览

子比主题大量交互走 WordPress Ajax，入口仍然是：

```txt
wp-admin/admin-ajax.php?action=动作名
```

注册方式保持 WordPress 标准：

```php
add_action('wp_ajax_user_signin', 'zib_ajax_user_signin');
add_action('wp_ajax_nopriv_user_signin', 'zib_ajax_user_signin');
```

命名习惯很清晰：

| 前缀              | 含义                         |
| ----------------- | ---------------------------- |
| `zib_ajax_*`      | 主题主流程 Ajax 回调函数     |
| `zibpay_ajax_*`   | Zibpay 支付、订单、资产 Ajax |
| `zib_bbs_ajax_*`  | 论坛模块 Ajax                |
| `zib_shop_ajax_*` | 商城模块 Ajax                |

动作名通常不带 `zib_` 前缀，例如 `user_signin`、`posts_save`、`follow_plate`、`submit_order`。

## 本地 Ajax 入口校准

本地主题入口 `action/function.php` 当前实际加载：

```txt
action/main.php
action/ajax.php
action/user.php
action/author.php
action/sign_register.php
action/comment.php
action/documentnav.php
action/media.php
action/new_posts.php
```

因此排查某个主流程 Ajax 时，先看 `action/function.php` 的加载列表，再按动作名搜注册：

```bash
rg -n "add_action\\('wp_ajax_{action}'|add_action\\('wp_ajax_nopriv_{action}'" 主题插件子主题/zibll
```

如果是支付、论坛或商城，再分别扩展到：

```bash
rg -n "add_action\\('wp_ajax_{action}'" 主题插件子主题/zibll/zibpay/functions
rg -n "add_action\\('wp_ajax_{action}'" 主题插件子主题/zibll/inc/functions/bbs/action
rg -n "add_action\\('wp_ajax_{action}'" 主题插件子主题/zibll/inc/functions/shop/action
```

几个容易误判的点：

- `wp_ajax_nopriv_*` 只表示游客能打到回调，不代表游客能完成写入；回调里仍可能要求登录、nonce、验证码、订单状态或权限。
- 主题响应函数是 `error => true|false` 的子比结构，不一定是 WordPress 原生 `success => true|false`。
- 前台 Ajax 多语言上下文由 `zib_locale_frontend_ajax_prefixes` 和 `zib_locale_frontend_ajax_actions` 控制。插件 action 如果不以 `zib_`、`zibpay_` 开头，又需要前台语言，应加入对应 filter。
- 同一业务可能先打开 modal，再提交动作。例如支付有 `pay_cashier_modal`、`order_pay_modal`、`initiate_pay`、`check_pay`；不要只看最后一个请求。

## 主题响应函数

子比在 `action/ajax.php` 中定义了统一响应函数：

```php
function zib_send_json_error($data = false, $type = 'danger')
function zib_send_json_success($data = false, $type = '')
```

本地源码里错误响应会写入 `error => true` 和 `ys => $type`，成功响应会写入 `error => false`，传入成功 `$type` 时才写 `type`。字符串参数会变成 `msg`，数组参数会与默认结构合并。

常见写法：

```php
if (!$user_id) {
    zib_send_json_error(__('请先登录', 'zib_language'));
}

zib_send_json_success(array(
    'msg'  => __('操作成功', 'zib_language'),
    'html' => $html,
));
```

主题很多旧流程会直接使用这两个函数，不一定使用 `wp_send_json_success()`。读源码时优先按子比响应结构理解前端处理。

## 登录注册动作

文件：

```txt
action/sign_register.php
```

核心动作：

| Action                  | 回调                             | 游客 |
| ----------------------- | -------------------------------- | ---- |
| `user_signin`           | `zib_ajax_user_signin`           | 是   |
| `user_signup`           | `zib_ajax_user_signup`           | 是   |
| `user_signin_nopas`     | `zib_ajax_user_signin_nopas`     | 是   |
| `signup_captcha`        | `zib_ajax_signup_captcha`        | 是   |
| `signin_captcha`        | `zib_ajax_signin_captcha`        | 是   |
| `resetpassword_captcha` | `zib_ajax_resetpassword_captcha` | 是   |
| `reset_password`        | `zib_ajax_reset_password`        | 是   |

这类动作会调用：

```php
zib_ajax_captcha_form_judgment()
zib_ajax_send_captcha()
zib_ajax_email_judgment()
zib_ajax_username_judgment()
```

登录成功后会触发 WordPress 原生 Hook：

```php
do_action('wp_login', $user->user_login, $user);
```

注册会经过：

```php
$errors = apply_filters('registration_errors', $errors, $sanitized_user_login, $email);
```

## 权限与校验

子比 Ajax 常见校验函数：

```php
zib_ajax_wp_verify_nonce()
zib_ajax_verify_nonce()
zib_ajax_man_machine_verification()
zib_ajax_captcha_form_judgment()
zib_ajax_is_verify_user()
zib_ajax_debounce()
```

写入类动作至少确认：

1. 当前用户是否登录。
2. nonce 是否正确。
3. 用户是否能操作目标对象。
4. 目标 post、term、comment、order 是否存在。
5. 状态是否允许变化。
6. 金额、积分、库存、权限是否由服务端重新计算。

游客动作只适合登录注册、验证码、搜索、展示弹窗、公开列表、支付游客流程等明确允许的场景。

## 调试方式

浏览器 Network 面板重点看：

- `admin-ajax.php` 是否请求成功。
- `action` 是否和源码注册一致。
- 是否带 `_wpnonce`、`post_id`、`id`、`type` 等必要参数。
- 响应 JSON 是否是子比 `zib_send_json_*` 结构。
- 是否被 WAF、CDN、防火墙、缓存或登录态拦截。

PHP 侧调试建议写受控日志，不要把 SQL、服务器路径、密钥、支付回调原文直接返回给前端。
