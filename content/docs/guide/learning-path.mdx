子比主题功能很多，不适合从某个单点功能开始随机阅读。更稳的方式是先建立源码、配置和数据流的整体认知，再按网站类型补齐内容、用户、商城、论坛和二次开发能力。

这页不是官网文章列表的搬运，而是把官网阅读指引映射到本站已经沉淀的开发文档：每一步都对应可继续深入的文档页。

## 阅读前准备

准备好子比主题、子主题和插件源码，并明确这次要修改的是配置、模板、Hook、Ajax 还是独立插件。准备阅读支付、商城、会员和积分链路时，再记录对应的主题版本和插件版本。

## 按网站类型阅读

| 网站类型     | 优先阅读                                                               |
| ------------ | ---------------------------------------------------------------------- |
| 博客、资讯站 | 主题常用设置、站点框架与导航、首页与归档列表、文章正文、SEO、分享      |
| 教程文档站   | 文章正文、古腾堡块、目录树、图片灯箱、搜索体系、SEO、百度提交          |
| 资源下载站   | 用户系统、Zibpay、付费下载、媒体上传、用户资产、内容审核               |
| 会员资源站   | 登录注册、用户成长、VIP 会员、积分余额、付费内容、消息通知             |
| 实物商城     | 商城模块、商品字段、购物车、发货售后、优惠码、商城用户中心             |
| 社区论坛     | 用户系统、论坛模块、论坛排序、论坛小工具、消息通知、内容审核           |
| 定制开发项目 | 源码结构、Codestar Framework、主题扩展、Hook、Ajax、模板覆盖、插件制作 |

## 开发者阅读顺序

如果你的目标是做二次开发，而不是只配置站点，建议按这个顺序：

1. [源码结构](/docs/source-structure)：知道主题目录和模块位置。
2. [加载顺序](/docs/api/loading)：知道文件什么时候加载。
3. [数据模型](/docs/api/data-models)：理解文章、用户、论坛、商城、订单和 meta。
4. [主题函数](/docs/api/functions)：先复用主题已有函数。
5. [Hook 与过滤器](/docs/api/hooks)：用 Action 和 Filter 做无侵入扩展。
6. [Ajax 动作](/docs/api/ajax)：理解 nonce、权限、返回格式和缓存边界。
7. [Codestar Framework](/docs/codestar-framework)：扩展后台设置、Meta、小工具和自定义字段。
8. [模板覆盖](/docs/api/templates)：最后再考虑覆盖模板。

示例代码尽量保持子比主题风格：命名函数、`array()`、WordPress Hook、Ajax action、`_pz()`、`zib_get_*_meta()`、`zib_update_*_meta()`、`zib_send_json_success()` 和 `zib_send_json_error()`。

## 遇到问题怎么回到路线

| 现象           | 回到哪一步                                              |
| -------------- | ------------------------------------------------------- |
| 页面打不开     | 第一阶段，检查 DNS、站点绑定、HTTPS、伪静态             |
| 样式或导航不对 | 第二阶段，检查主题设置、菜单、背景、明暗模式            |
| 首页不会搭     | 第三阶段，检查模块、小工具、页面设置、归档列表          |
| 文章展示异常   | 第四阶段，检查文章模板、正文 Hook、古腾堡块、媒体       |
| 登录注册失败   | 第五阶段，检查 SMTP、验证码、人机验证、Ajax、缓存       |
| 支付或订单异常 | 第六阶段，检查 Zibpay、回调、HTTPS、缓存、订单状态      |
| 论坛权限异常   | 第七阶段，检查板块、帖子、用户权限和发帖限制            |
| 想做功能扩展   | 第八阶段，先找 Hook、Ajax、短代码、模板和 Codestar 入口 |
